# Feature Detail: Strong Typing Constraints

**Feature ID**: 008  
**Name**: Strong Typing Constraints  
**Description**: 禁止新增弱类型 map 作为请求/响应载体  
**Status**: Implemented  
**Created**: 2026-02-06  
**Last Updated**: 2026-02-06

## Overview

Strictly enforce Go's type safety by forbidding `map[string]interface{}` for API payloads in new code.
Developers MUST define explicit structs for all API requests and responses.
This reduces runtime type assertion errors and improves IDE autocompletion/refactoring support.

## Latest Review

Constitution Principle II and Engineering Standards explicitly forbid untyped maps.
Code reviews enforce this rule. `cws-lib-go` usage supports this by providing typed structs.

## Key Changes

1. Policy definition in Constitution
2. Code review guidelines updated
3. Refactoring of legacy untyped code (ongoing)

## Implementation Notes

- Use `json` struct tags for API marshaling.
- Use pointers for optional fields to distinguish zero-values from unset values.

## Future Evolution Suggestions

- Add linter rules to automatically detect usage of `map[string]interface{}` in service layers
