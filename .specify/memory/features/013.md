# Feature Detail: Flink Workspace Capacity Allocation

**Feature ID**: 013\
**Name**: Flink Workspace Capacity Allocation\
**Description**: Separate paid Workspace lifecycle from authoritative PRE capacity, namespace, and implicit queue reconciliation.\
**Status**: Implemented; runtime and rollout verification in progress\
**Created**: 2026-07-16\
**Last Updated**: 2026-07-16

## Overview

This feature introduces `alicloud_flink_workspace_capacity_allocation` as the single authoritative owner of a Workspace's fixed, cross-zone fixed, maximum capacity, complete namespace set, and each namespace's implicit `default-queue`. `alicloud_flink_workspace` remains the owner of purchase, billing, network, HA topology, create-time `initial_capacity`, import, and release. One Workspace may have only one allocation owner across Terraform states and processes; the provider process lock is not cross-state uniqueness.

## Latest Review

The provider integration contains the reviewed allocation resource, topology adapter, Workspace initial-capacity mode, and registry/coordinator cleanup. The reviewed cws-lib pin is `fa9c9495be328abea48ab38fb6cafbdd0983f1d3`: it serializes non-nil namespace `ResourceSpec`, preserves legacy nil-spec behavior, uses the explicit Workspace ID, and reports only a confirmed Create-success/post-read failure as typed `FlinkPostCreateReadError`. Any such typed error, whether its cause is 404 or non-404, denotes confirmed Create/post-read ambiguity; direct service/API/business rejections remain terminal, while ordinary `FlinkSDKError` transport failures retain the general ambiguous-write policy. Local Go integration checks pass. OpenTofu runtime, provider-binary/mirror, temporary live-probe, `cws-lib-iac` compatibility validation, ten legacy-leaf, and canonical iac-env validation remain in progress.

## Key Changes

1. Allocation is PRE-only. Its first authoritative Read rejects POST before any cloud write. Workspace `initial_capacity` is an integer-CU, create-only input serialized only to `CreateInstance`; it is mutually exclusive with legacy `resource` / `ha.resource`, and new POST configurations fail before the parent purchase.
2. Allocation HCL is the complete authoritative namespace set. Missing namespaces are created, undeclared namespaces are removed, and reconciliation never deletes the last namespace. Namespace CU type is derived from the Workspace's pure single-zone or cross-zone mode and is retained through Read, import, and topology hashing.
3. Every namespace implicitly owns `default-queue`, with request equal to namespace fixed CU and limit equal to namespace maximum CU. A custom queue causes fail-closed behavior before the first cloud write. Internal capacity values use half-CU units for lossless observations, while the user-facing Workspace and namespace contract accepts integer CU only.
4. `implicit_topology_hash` is a sorted canonical `v1:<sha256>` over namespace CU type and every queue name/request/limit. It excludes used/status and other runtime fields, uses `schema.HashResource` for the namespace set, and is computed when all desired inputs are known.
5. Allocation Delete only detaches Terraform state with `SetId("")`; it performs no Workspace, namespace, or queue API call. Import accepts only the Workspace ID, sets both ID fields, performs no reconciliation, and lets the first Read import actual capacity, namespaces, queue hash, and observed tree.
6. Namespace Create uses the cws typed boundary: it copies the request, supplies explicit Workspace ID, maps cross-zone state, and writes initial `1 CU / 4 GiB` `ResourceSpec`. Only `FlinkPostCreateReadError` denotes Create/read ambiguity; string or HTTP-fingerprint inference is not used.
7. The unpublished `alicloud_flink_capacity_coordinator`, `capacity_management`, and `bootstrap_capacity` handshakes were removed without a stub or state upgrader. Unknown private coordinator state requires manual migration: record Workspace ID and complete absolute capacity, use the old provider to `state rm`, upgrade, declare allocation, import the Workspace ID, review the complete namespace set, then apply.

## Implementation Notes

- Legacy Workspaces without `initial_capacity` retain their existing `resource` / `ha.resource` schema, ForceNew behavior, Read/CRUD, import, and ten xuanji legacy-leaf no-diff target.
- Allocation-managed namespaces and queues must not be managed simultaneously by legacy child resources.
- Reconciliation persists the last actual tree before an error, uses authoritative Read/replan after each cloud write, and exposes a diagnostic-only sorted `observed_capacity_tree`.
- The historical `903038` probe established that omitting `ResourceSpec` produces an invalid zero allocation even with headroom. Task D resolves that provider/cws-lib boundary in code; the combined-provider live probe is still required.
