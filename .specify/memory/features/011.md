# Feature Detail: Split OTS Instance Resources

**Feature ID**: 011
**Name**: Split OTS Instance Resources
**Description**: Split the alicloud_ots_instance resource into alicloud_ots_instance and alicloud_ots_instance_vcu to separate logic.
**Status**: Planned
**Created**: 2026-01-20
**Last Updated**: 2026-01-20

## Overview

Currently, the `alicloud_ots_instance` resource handles both standard (SSD, HYBRID) and VCU instances. The logic is mixed within `resourceAliCloudOtsInstance`. This feature aims to split them into two separate resources: `alicloud_ots_instance` (for standard types) and `alicloud_ots_instance_vcu` (for VCU type), each with its own implementation function (`resourceAliCloudOtsInstance` and a new `resourceAliCloudOtsInstanceVCU`), to improve maintainability and code clarity.

## Latest Review

Initial planning phase.

## Key Changes

1. Create a new Terraform resource `alicloud_ots_instance_vcu`.
2. Implement `resourceAliCloudOtsInstanceVCU` function to handle VCU instance logic.
3. Refactor `resourceAliCloudOtsInstance` to focus on standard instances (SSD/HYBRID) and remove/minimize VCU specific logic (while maintaining necessary backward compatibility).
4. Update Terraform provider registration to include the new resource.

## Implementation Notes

- The existing `alicloud_ots_instance` must continue to support existing SSD/HYBRID instances.
- The new resource `alicloud_ots_instance_vcu` will be the preferred way to create VCU instances.
- Error handling and validation should guide users to the correct resource.

## Future Evolution Suggestions

- Deprecate VCU support in `alicloud_ots_instance` completely in a future major version.
