# Feature Detail: ADBPG Resource Management

**Feature ID**: 012  
**Name**: ADBPG Resource Management  
**Description**: AnalyticDB PostgreSQL (ADBPG) 资源与数据源的 Terraform 管理，使用新的 adbpg 命名替代旧的 gpdb 命名  
**Status**: Implemented  
**Created**: 2026-06-22  
**Last Updated**: 2026-06-23

## Overview

This feature introduces a complete set of Terraform resources and data sources for managing Alibaba Cloud AnalyticDB PostgreSQL (ADBPG) instances and related sub-resources. The existing provider uses `gpdb` naming (derived from Greenplum Database), which is outdated. The new implementation uses `adbpg` naming to align with the current product branding and leverages the strongly-typed API layer in `pkg/cws-lib-go` (adbpg domain) instead of direct SDK calls.

## Latest Review

Implementation completed 2026-06-23. All 7 resources and 3 data sources implemented with service layer (31 methods). Two tasks deferred (T045, T046) due to read-only submodule — RPC fallback methods used for ModifyBackupPolicy and ModifyAccountDescription. Build, formatting, and vet checks pass.

## Key Changes

1. Introduce 7 new Terraform resources with `alicloud_adbpg_*` naming (instance, account, database, connection, security_ip_array, backup_policy, ssl)
2. Introduce 3 new Terraform data sources with `data.alicloud_adbpg_*` naming (instances, accounts, zones)
3. Implement service layer (`service_alicloud_adbpg.go`) following the strict Resource -> Service -> API -> SDK architecture
4. Extend provider connectivity layer to support `AdbpgAPI` client creation via cws-lib-go
5. All new code uses strongly-typed structs from cws-lib-go, with pagination and state polling encapsulated in service/API layers

## Implementation Notes

- The existing `gpdb` resources remain untouched; the new `adbpg` resources coexist alongside them
- The cws-lib-go API layer (commits aa4d774 and 0b9fa3a) provides the typed API wrappers that the service layer calls
- StateRefreshFunc and WaitFor* patterns must be implemented in the service layer for instance status transitions
- The API layer also contains vector/AI, diagnostics, and governance APIs that can be exposed as additional resources in future iterations

## Future Evolution Suggestions

- Add resources for streaming data sources and streaming jobs (`alicloud_adbpg_streaming_data_source`, `alicloud_adbpg_streaming_job`)
- Add resources for vector database capabilities (namespaces, collections)
- Add data sources for backups, diagnostics, and instance plans
- Consider deprecating the old `gpdb` resources in favor of `adbpg` with migration guidance
