## Overview

This feature upgrades the `alicloud_logtail_config` resource and its service layer to use the latest Logtail Pipeline Config capabilities. It intentionally introduces a redesigned, clearer configuration model (schema) to match the new pipeline concepts, without requiring backward compatibility with the legacy LogtailConfig behavior.

## Latest Review

Plan created with design artifacts (data model, schema/service contracts, quickstart) and constitution compliance reviewed.

## Key Changes

1. 2026-02-12: Created requirements spec for migrating from legacy LogtailConfig to Logtail Pipeline Config.
2. 2026-02-12: Defined expectations for a clearer, stable, diff-friendly schema model.
3. 2026-02-12: Created implementation plan and design artifacts for schema + service migration (Spec 004).

## Implementation Notes

- Keep strict layered architecture: Resource -> Service -> API wrapper.
- Avoid opaque/weakly-typed configuration models where possible; prefer structured configuration with validation.
- Ensure all core operations for this resource rely on the new pipeline-config capability (no legacy endpoint reliance).
- Plan artifacts are located under `.specify/specs/004-logtail-pipeline-config/` (plan.md, research.md, data-model.md, contracts/, quickstart.md).

## Future Evolution Suggestions

- Add a data source for querying existing pipeline configs.
- Expand schema coverage as new pipeline components or features become commonly used.
