# Feature Detail: Layered Architecture Provider

**Feature ID**: 002  
**Name**: Layered Architecture Provider  
**Description**: Strict separation of concerns (Resource -> Service -> API -> SDK) for maintainability.  
**Status**: Implemented  
**Created**: 2026-01-22  
**Last Updated**: 2026-01-22

## Overview

Enforces a strict architectural hierarchy to decouple Terraform logic from API interaction logic. The hierarchy is: Provider Layer → Resource/DataSource Layer → Service Layer → API Layer (CWS-Lib-Go) → SDK Layer. This ensures that resource files remain focused on schema mapping and state management.

## Latest Review

Architecture principles defined in `docs/development_guide.md` and Constitution.

## Key Changes

1. All CRUD logic encapsulated in Service layer.
2. Resource headers MUST NOT import SDK packages directly.
3. State polling logic implemented via `StateRefreshFunc` in Service layer.
4. Pagination logic encapsulated strictly within Service `*_api.go` files.

## Implementation Notes

- Resources interact only with Service interfaces.
- `d.SetId("")` used to handle Not Found errors in Read.
- Wait functions provided by Service layer for Create/Delete operations.

## Future Evolution Suggestions

- Automatic linting rules to detect architecture violations (e.g. direct SDK imports in resource files).
