# Feature Detail: Layered Architecture

**Feature ID**: 004  
**Name**: Layered Architecture  
**Description**: Resource -> Service -> API -> SDK 严格分层架构  
**Status**: Implemented  
**Created**: 2026-02-06  
**Last Updated**: 2026-02-06

## Overview

Enforces a strict separation of concerns:
- **Resource Layer**: Handles Terraform schema, CRUD operations, and state management.
- **Service Layer**: Encapsulates business logic, API orchestration, and error handling.
- **API Layer (wrapper)**: Provides a uniform interface to the SDK.
- **SDK Layer**: Raw Alibaba Cloud SDK client.

This structure prevents logic leakage into Resource definitions and promotes reusability.

## Latest Review

Codebase largely adheres to this pattern. `resource_*.go` files invoke methods in `service_*.go`.
Direct SDK usage in resources is discouraged/deprecated.

## Key Changes

1. Defined strict boundaries between Resource and Service layers
2. Migrated legacy resources to use Service layer pattern
3. Established `cws-lib-go` as the standard API/Service intermediary

## Implementation Notes

- New resources MUST follow this pattern.
- Refactoring legacy code is ongoing.
- `Constitution` explicitly mandates this structure (Principle I).

## Future Evolution Suggestions

- Complete migration of all legacy resources to Service layer
- Further decouple API layer to support mock-based testing without network calls
