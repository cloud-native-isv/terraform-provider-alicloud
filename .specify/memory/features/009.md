# Feature Detail: Fix AliKafka Resource Implementation

**Feature ID**: 009  
**Name**: Fix AliKafka Resource Implementation  
**Description**: Comprehensive fix for AliKafka resource state persistence, API layer integration, and state lifecycle management issues.  
**Status**: Implemented  
**Created**: 2026-01-25  
**Last Updated**: 2026-01-25

## Overview

This feature addresses critical issues in the existing AliKafka resource implementations (`alicloud_alikafka_instance` and `alicloud_alikafka_deployment`) that prevent proper infrastructure management through Terraform. The fixes ensure complete state synchronization, modern API integration, and proper handling of Kafka instance lifecycle states.

## Latest Review

Based on user report identifying three main issue categories:
1. State persistence problems with missing fields in tfstate
2. Outdated API layer implementation not using latest CWS-Lib-Go 
3. Improper state lifecycle management across order creation → deployment → running states

## Key Changes

1. Complete state persistence for all computed attributes in both AliKafka resources
2. Migration to use only CWS-Lib-Go Kafka API layer (`github.com/cloud-native-tools/cws-lib-go/lib/cloud/aliyun/api/kafka`)
3. Implementation of proper state transition handling for multi-stage Kafka instance lifecycle
4. Consistent error handling using standard patterns (IsNotFoundError, IsAlreadyExistError, NeedRetry)
5. Backward compatibility maintenance with existing Terraform configurations

## Implementation Notes

- Both `alicloud_alikafka_instance` and `alicloud_alikafka_deployment` resources need updates
- Service layer functions should be shared between both resources for consistency
- All computed fields must be properly set in Read operations and persisted in state
- State refresh functions must handle all possible Kafka instance states (0, 2, 3, 4, 5)
- Integration must follow layered architecture principles (Resource → Service → API → SDK)
- Use CreateInstance directly (bypassing order system) as per clarification
- Include all fields available in CWS-Lib-Go API responses and derive complex fields like vswitch_ids and selected_zones
- Maintain backward compatibility with existing Terraform configurations

## Key Changes from Plan

1. **API Integration**: Use CreateInstance directly instead of order-based creation
2. **State Definitions**: Explicit state mappings - 0=Order Processing, 2=Creating, 3=Configuring, 4=Starting, 5=Running  
3. **Field Persistence**: Include all available CWS-Lib-Go API fields and derive complex fields from basic information
4. **Service Layer**: Shared service functions for both AliKafka resources ensuring consistency

## Future Evolution Suggestions

- Consider consolidating AliKafka instance creation and deployment into a single resource if feasible
- Add comprehensive acceptance tests covering all state transitions and edge cases
- Monitor for additional state persistence issues in other AliKafka-related resources
